R2. Separate attention savings from projection savings
The dense baseline has a rank-128 output projection; the compressed cells use rank 64. Table 9 assigns these
projections 20.97M and 10.49M MACs respectively. Consequently: (Manuscript, p. 24, Table 9.)
Reported total saving = 76.86 − 59.63 = 17.23M MACs
Projection difference = 20.97 − 10.49 = 10.48M MACs
Projection share of the saving = 10.48 / 17.23 ≈ 61%
Replacing only the baseline projection cost gives 66.38M MACs, reducing the accounting advantage to
approximately 10.2%, not 22%. This is an accounting sensitivity calculation, not a prediction of retrained
accuracy or measured latency; the remaining operation counts still require audit.
Required experiment: add a mechanism-matched dense baseline with the same projection ranks,
normalization, positional treatment and compatible sink treatment. Retain the original Normal model as an
as-run reference. A separately tuned, equal-budget dense model is also useful for deployment comparison.
Do not conflate parameter matching with architectural matching, or reference-output agreement with
comparison fairness.
Submission condition: every headline improvement must state whether it is attributable to
compression/routing, changed projections, a different prediction head, or an implementation choice.

R3. Fixed top-k is not a fixed information budget
At k = 16, one selected routing token in (4,8) expands to two KV blocks, whereas selections in (8,4) can
collide on the same KV block. The draft also reports approximately 14 unique selected blocks for the
equal-rate reference versus 10 for the dual-rate cell. Thus, the original factorial compares complete
configurations; it does not isolate routing resolution independently of realized coverage. (Manuscript, pp.
5–6, §§3.3–3.4.)
Required experiment: retain the fixed-k factorial, then add comparisons that fix the number of unique, valid
KV blocks after mapping and deduplication, at each fixed cKV. Specify how index scores are aggregated to
block scores and how the selector fills the budget. Apply identical causality rules and handle early queries
with too few eligible blocks explicitly.
Log candidate count, eligible count, unique selections, duplicate rate, selected fraction, lag distribution and
the union of raw-time receptive fields. The compressor overlaps adjacent windows, so block count times cKV
is not an exact measure of unique temporal coverage. For comparisons across cKV, add a separate
coverage-matched sensitivity analysis rather than claim that all budgets can be matched simultaneously.
R4. An untrained indexer is not necessarily a fixed route
The router reuses queries and hidden representations produced by trainable components. Even if
indexer-exclusive parameters receive no direct task-loss gradient, the selected blocks can change as those
inputs change. The repeated phrase “routing is fixed at initialization” is therefore not established by the
reported gradient audit. (Manuscript, p. 5, §3.3; p. 26, Table 10.)
Required audit: track route overlap and entropy on fixed probe inputs at initialization and across epochs.
Save parameter snapshots and distinguish a missing gradient from a zero gradient; check actual optimizer
updates. Separate backbone, indexer and data-loader random seeds. Compare the present indexer with a
genuinely fixed mask and with one explicitly trained selector.
A teacher-guided block-importance loss is a practical learned-routing control, but report its extra training
cost and test-time requirements. DeepSeek-V4 explicitly includes an indexer warm-up stage, so its training
regime is not interchangeable with the manuscript’s untrained-indexer setting. (DeepSeek-AI, 2026)
R5. Rebuild the evidential chain after the mapping correction
Some mechanism probes are retained from checkpoints predating the mapping correction. They cannot
substantiate the corrected method’s mechanism. Regenerate those results and their figures from a single
versioned implementation, or remove them from the evidential argument while retaining their development
history in the archive. (Manuscript, p. 9, §4.3.)
Extend the reported future-invariance suite to indexer scores, block boundaries, ties, padding and every
tested rate pair. Zero future gradients alone cannot exclude future dependence through a hard discrete
selector. The existing perturbation-based checks are valuable; the revised report should state their coverage
and preserve the passing logs, rather than assume a failure.

R6. Make optimized forecasting cost the primary comparison
Equation 1 uses the final hidden state of a single block. The manuscript’s last-query audit reports Normal at
2.6–3.9 ms versus DRRA at 5.8–8.6 ms per batch-32 pass. That comparison reverses the full-layer efficiency
ranking. It must lead the efficiency results and the accuracy–latency frontier. (Manuscript, pp. 4 and 14, §§3.2
and 4.7.)
For the stated one-block, pointwise-readout architecture, the last query can attend to all historical keys
without calculating all query outputs. Its attention-core cost is linear in L for fixed width. Verify forecast and
parameter-gradient equivalence before using this pruned graph for training; stochastic operations must be
handled consistently. Do not generalize the simplification to deeper architectures without tracing their
dependencies.
Required revision: report FULL operator timings separately from forecast-required timings, optimize every
comparator legitimately, and replace Figure 6 with the deployment-relevant frontier. Full-layer savings may
remain useful in an architecture whose head needs all temporal outputs, but cannot support the current
per-forecast efficiency headline.
R7. Check whether the PatchTST experiment actually routes
With lookback 256, patch length 16 and stride 8, PatchTST has 31 tokens before optional end padding,
approximately 32 with common padding. Compression at cR = 4 or 8 then gives only about eight or four
routing candidates. If k = 16 is retained and the module acts along the patch axis, all available candidates are
selected: routing resolution is not meaningfully tested. (Manuscript, p. 10, §4.5; p. 23, Table 8.) (Nie et al.,
2023)
This is an implementation-dependent hypothesis, not a confirmed bug. Report the actual tensor axis, patch
padding, candidate count, k and selected fraction. At L = 1024 the same patching yields only about 128
tokens, so cR = 8 with k = 16 may still select everything. Use a smaller budget, such as k = 4 or 8, or a
sufficiently longer token sequence, and verify active selection in every cell.
Do not interpret small transfer effects as evidence that a strong backbone washes out routing until saturation
is excluded. Include the original dense PatchTST backbone and the no-routing compressed backbone in both
accuracy and speed comparisons.
R8. Reconcile the remaining accounting before extrapolation
Table 1 lists 17 softmax columns for (32,4), but its stated C + W + 1 gives 256/32 + 16 + 1 = 25. Check
whether the table is wrong or W changed. Also expose the number hI and dimension dI of scoring heads: the
dot-product routing term is generally hI × dI × NQ × (L/cR), where NQ is the number of evaluated queries.
Equation 2 assumes a particular head arrangement that requires tensor-shape verification. (Manuscript, pp. 6,
15 and 24.)
Recompute every affected total and scaling curve after these audits. Matching one script to another script using the same
assumptions is not an independent validation of the assumptions.

These tests distinguish redundancy of the observed series from preservation of the information needed for

A useful analytical starting point
For a checkpoint-level comparison with matched representations, let ofull denote uncompressed attention,
oall attention to all compressed blocks, and oroute routed compressed attention. The triangle inequality gives:
||ofull − oroute|| ≤ ||ofull − oall|| + ||oall − oroute||
With fixed compressed logits and values, suppose routing discards attention mass τ from the all-block
distribution, the retained set is nonempty, and every value norm is bounded by Vmax. Renormalization then
gives:
||oall − oroute|| ≤ 2Vmaxτ
To see this, write the all-block output as (1 − τ)μkept + τμremoved; its difference from μkept is τ(μremoved −
μkept). Keep local and sink contributions in the accounting. This is an elementary proposed diagnostic, not a
novelty claim or a guarantee of forecast accuracy.
Required evidence: measure compression discrepancy and discarded mass, then test whether they predict
the observed rate effects. Also measure forecast changes under targeted interventions, because an
attention-output bound alone does not establish predictive importance. For a more ambitious Neural
Networks submission, develop and validate a genuinely informative analysis beyond this elementary
decomposition.
Potential reusable result: a held-out-validated selection guide connecting signal structure, token
geometry and realized computational budget to when compression alone or compression plus routing
is preferable.

P1 / RELIABLE INFERENCE, PERFORMANCE AND REPRODUCTION
7. Strengthen the statistics and systems evidence
Separate three sources of uncertainty
Training randomness: preserve paired-seed analyses for the fixed dataset. Temporal uncertainty: evaluate
rolling forecast origins or independent time blocks and retain per-origin losses. Dataset variation: report
conditional effects by dataset and avoid counting every seed or related ETT series as an independent domain.
These answer different questions; one large seed count does not replace the others. (Demšar, 2006, for
across-dataset comparison principles)
For per-origin inference, use a paired moving-block or other dependence-aware resampling scheme with
block-length sensitivity; do not bootstrap overlapping windows as independent observations. Report test
MSE and MAE, uncertainty for the interaction and simple effects, and the multiplicity family for primary
contrasts. State whether each interval concerns a paired mean, median or another estimand: a
mean-difference interval and a signed-rank test need not agree.
A nonsignificant difference is not evidence of preserved accuracy. To claim that a cheaper configuration
retains performance, predefine a defensible non-inferiority margin and estimate whether the data support it.
Do not select a convenient margin after seeing the results. Preserve the original five-seed analysis, its
extension and the new confirmation as distinguishable stages. (Manuscript, pp. 7–8 and 11–12, §§4.1–4.6.)
Benchmark optimized implementations, not only operation counts
Use the existing Apple CPU measurements as one platform and add a representative GPU or a clearly
justified second deployment platform. Compare against the strongest valid dense implementation, including
fused attention where compatible. FlashAttention demonstrates why reduced memory traffic and arithmetic
counts must be distinguished. (Dao et al., 2022)
Measure forecast-required latency at batch 1 and a realistic batched setting, throughput, peak allocated
memory, forward-plus-backward time and end-to-end training time. Report dtype, kernel, compilation mode,
thread count, synchronization, warm-up, device and software versions. Alternate timed configurations within
rounds and report paired uncertainty; include compression, index scoring, top-k, masks, transfers and the
prediction head in the timed path.
The current implementation pays the full compressed attention width despite sparse masks. Report this
explicitly and profile where time is spent. A GPU sparse kernel is valuable only if a measured bottleneck
justifies developing it; do not require bespoke kernel work merely to enlarge the paper.
Treat energy as a measurement question
Move the present arithmetic-to-energy projections to a qualified appendix, or replace them with sustained,
instrumented measurements. For joules per forecast, state whether the boundary is device-only or
whole-system, report idle treatment, integrate power over a timed workload, and quantify measurement
resolution. MAC reductions alone establish neither the size nor the sign of an energy improvement.
(Manuscript, §§4.8 and Appendix D.)
Release a tagged code archive, dataset hashes, configuration files, raw paired results, profiler traces,
corrected tests and one-command table/figure regeneration. Distinguish the draft’s claims that artifacts exist
from an independently verified release; archive the exact version used for submission.
